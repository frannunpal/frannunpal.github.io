Cities — Lighting & Shadow System (Three.js / R3F)

Rendering pipeline for 3D city lighting using Three.js R3F, SunCalc astronomical calculations, and reactive light wrappers + native shadow maps via directional light.

Note: The previous deck.gl system used LightingEffect, ShadowMapEffect (custom FBO + PCSS), and SunLightingExtension. The current Three.js R3F system uses reactive light wrappers (Zustand subscriptions in-place), native Three.js shadow maps via ShadowDirLight, and mergedBuildingMaterial shader. See cities-threejs-architecture for full migration context.

Coordinate System — CRITICAL (2026-06-17, valid for BOTH backends)

Three.js R3F uses Y-up: [X=right, Y=up, Z=forward]. SunCalculationService.getSunDirection() returns Y-up (astronomical convention): [East=X, Up=Y, North=Z].

Since both Three.js and SunCalc use Y-up, no Y↔Z swap is needed for the Three.js consumer. The ShadowDirLight component computes sun position directly:

The deck.gl consumers of getSunDirection() required Y↔Z swap (documented in commit d1bdbd9). This is irrelevant for the Three.js path.

Shadow System (Native Three.js)

In Three.js R3F, shadows are handled natively by the renderer. No custom Effect, FBO, or shader module needed.

Pipeline

  1. ShadowDirLight — directional light with castShadow, shadow-mapSize, shadow-bias, shadow-radius
  2. Canvas — shadows="basic" enables shadow map
  3. Meshes — castShadow on buildings, receiveShadow on ground/base
  4. MergedBuildingMesh — customDepthMaterial={depthMat} ensures ShaderMaterial buildings participate in shadow pass

Unlike deck.gl, there is NO PCSS blocker search / penumbra estimation. Three.js uses built-in PCF (Percentage-Closer Filtering) with shadow-radius controlling softness.

Scanner — No Shadow Conflict

In Three.js, the scanner ShaderMaterial (mergedBuildingMaterial) sets transparent: true and provides a customDepthMaterial (MeshDepthMaterial) for the shadow pass. No conflict between scanner and shadows — they coexist:

The customDepthMaterial ensures the shadow camera renders correct depth values even when the main material has transparency/custom color logic.

SceneFog

CRITICAL: The mergedBuildingMaterial shader has fog: false on the ShaderMaterial because it implements fog manually in GLSL (smoothstep(fogNear, fogFar, dist)). This prevents Three.js from overwriting the custom fog uniform.

Post-Processing (SSAO + Bloom)

Isolated in <SsaoBloomPasses /> so param updates don’t re-render SceneContent.

Sun Position Calculation

Uses SunCalc (npm: suncalc ^1.9.0) for real astronomical sun position.

Function Chain

SunCalculationService.getSunAnglesFromTimeOfDayAndCoords(timeOfDay, coords, date?)
  │
  ├── Converts local timeOfDay → UTC using longitude offset
  ├── Creates UTC Date object for SunCalc
  │
  └── SunCalc.getPosition(date, lat, lon)
        │
        ├── altitude (radians → degrees) → **sunElevation**
        └── azimuth (radians → degrees, +180° normalization) → **sunAngle**

Direction Convention (Three.js)

getSunDirection(azimuth, elevation) returns FROM-scene-TO-sun in Y-up: [East, Up, North].
Three.js R3F also uses Y-up: [X=right, Y=up, Z=forward].
No swap needed — the ShadowDirLight computes position directly from sunAngle/sunElevation.

Troubleshooting

Shadows not appearing

  1. shadowEnabled not set on layer — each layer needs shadowEnabled: true (or ShadowLayerExtension)
  2. Sun elevation too low — shadows only render when sunElevation > 5° (below that the ShadowMapEffect disables itself)
  3. Scanner active — see Scanner Pipeline Conflict (CRITICAL)
  4. Light size too small — lightSize < 0.1 makes PCSS penumbra effectively zero (hard shadows that may be invisible on low-res targets)
  5. Shadow map resolution — mapSize: 2048 may be too low for wide city views with tall buildings

Shadow acne / Peter Panning

Shadows not appearing (Three.js)

  1. castShadow not set on meshes — buildings need castShadow=true, ground/base need receiveShadow=true
  2. Canvas shadows="basic" — must be set on the R3F Canvas
  3. Sun elevation too low — ShadowDirLight sets intensity=0 when sunElevation < 0
  4. ShadowMapType — PCFSoftShadowMap deprecated, falls back to PCFShadowMap automatically

Buildings too dark / no directional variation

  1. ShadowDirLight.intensity set to 0 at night — check sunElevation. Daytime should be directionalIntensity (1.5 default)
  2. Ambient too low — ambientIntensity should be ≥ 0.2 for visible fill light
  3. ShaderMaterial uniforms — uSunDir, uSunColor, uAmbientStrength must be set from store subscription

Fog

City invisible at night: fogFar too short. Minimum: fogFar ≥ 800 for night, ≥ 500 for dusk. Runtime crash: set fog: false on ShaderMaterial and handle fog manually in GLSL (smoothstep(fogNear, fogFar, dist)).
