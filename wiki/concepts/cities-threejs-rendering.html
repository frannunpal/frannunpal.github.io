Cities — Three.js Rendering System

Sistema de renderizado 3D con @react-three/fiber (R3F): geometría merged, shaders custom, post-processing.

El sistema anterior (deck.gl GeoJsonLayer + LayerExtension) está archivado. Ver cities-threejs-architecture para la arquitectura general.

Coordinate System

Two coordinate conventions coexist in the pipeline:

MapGenerator → Three.js Conversion

MapGenerator: XY = footprint plane, Z implicit
Three.js: XZ = ground plane, Y = up

Conversion in convertToThreeScene.ts:

ExtrudeGeometry Convention (CRÍTICO)

ExtrudeGeometry crea geometría con:

  • XY = footprint (plano del mapa)
  • Z = height (dirección de extrusión)

Esto difiere de BoxGeometry/CylinderGeometry/SphereGeometry que usan Y = height por defecto. Implicaciones:

AspectoExtrudeGeometryPrimitives (Box/Cylinder/Sphere)
Height axisZY (require rotateX(PI/2))
Horizontal facesabsN.z > 0.9absN.y > 0.9
Window UV (X-facing)vec2(pos.y, pos.z)vec2(pos.x, pos.y)
Window UV (Y-facing)vec2(pos.x, pos.z)vec2(pos.y, pos.x)

Geometry Pipeline

convertToThreeScene()

Convierte Building[] + GeneratedMapData → THREE.Group listo para render:

convertToThreeScene(buildings, mapData)
│
├── buildMergedBuildingGeometry(buildings)
│     └── 1 solo BufferGeometry con todos los edificios
│           ├── position: Float32BufferAttribute (vértices merged)
│           ├── color: vertex colors (height-based)
│           ├── buildingId: índice numérico para selection/hover
│           └── buildingHeight: altura para scanner range
│
├── roadsToMesh(roads, color, lineWidth)
│     └── Mesh con MeshBasicMaterial + UVs para RoadMarkingsMaterial
│
├── polygonToShapeMesh(parks/river/sea/coast)
│     └── Mesh con MeshStandardMaterial + opacity
│
└── group.rotation.x = -PI/2 → todo al XZ ground plane

NaN Guards (3 niveles)

Coordenadas NaN en footprints (jsts buffer, PolyK slice, streamlines) causan crashes silenciosos. Guards aplicados:

NivelUbicaciónAcción
1buildMergedBuildingGeometry — loop principalisFinite(v.x) && isFinite(v.y) → skip building entero
2createExtrudeGeometryisFinite → retorna BufferGeometry() vacío
3roadsToMesh + polygonToShapeMeshisFinite → skip segment/polygon

Shader Materials

mergedBuildingMaterial.ts

ShaderMaterial custom para el merged building mesh. Reemplaza MeshStandardMaterial con un shader GLSL completo:

Features:

  • Ventanas procedurales — grid basado en floorHeight + building hash determinista
  • Iluminación — uSunDir, uSunColor, uAmbientStrength (desde store, imperativo)
  • Scanner — dot grid + sweep integrado (uEnabled uniform)
  • Selection dimming — uUnselectedOpacity para edificios no seleccionados
  • Fog — fogColor, fogNear, fogFar (THREE.Fog params)
  • Reflection — uWindowReflectionIntensity, uCameraPosition para envMap simulado
  • Tint — uTintColor, uShininess, wireframe (desde store)

Uniform update pattern (Paso 5):

Las uniforms animadas (sun, ambient, tint, windows, fog) se actualizan imperativamente vía useCitiesStore.subscribe() en un solo callback, no con selectores individuales. Esto evita ~12 selectores + 4 useEffects que re-renderizarían MergedBuildingMesh ~60×/s durante el ciclo día/noche.

buildingScannerMaterial.ts

ShaderMaterial standalone para el scanner (sin ventanas ni iluminación). Usado por ScannerMesh cuando scannerActive=true y el edificio NO está en el merged mesh.

roadMarkingsMaterial.ts

ShaderMaterial para carreteras con marcas viales procedurales (líneas discontinuas). Reemplaza MeshBasicMaterial de roadsToMesh.

Context Lost Handling

El Canvas R3F registra handlers en el DOM canvas para webglcontextlost / webglcontextrestored:

El Canvas está siempre montado, por lo que el contexto WebGL se crea una vez y estos handlers lo protegen durante toda la sesión.

Frameloop

frameloop="always" — originalmente era "demand" pero causaba WebGL context loss durante generación con Web Worker: los progress updates (30+ store changes en <1s) disparaban StoreInvalidator.invalidate() en ráfaga → GPU sobrecargada.
